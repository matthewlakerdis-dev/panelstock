# Fabrication toolbox talks

The existing PanelStock Worker serves the module at `/toolbox`. After the Worker release, the existing custom-domain route allows `https://cnc.panelstockhq.com/toolbox`; no DNS change, new Worker or storage binding is required. This URL is a deployment target, not confirmation that the module is live.

## Access and workflow

Open Toolbox Talks from the signed-in PanelStock Web or Mobile menu. No separate toolbox username/PIN form is used. A one-use ticket (60 seconds) is exchanged for a toolbox-only session bound to the original PanelStock session; it cannot outlive that session and is invalid after logout or account access changes. Only the short ticket travels in the URL fragment, which is removed immediately on arrival. The session bearer stays out of the URL. Direct unauthenticated visits show a link back to PanelStock. An administrator enables **Run toolbox talks** (`factory.toolbox`) for the supervisors or their role. This permission is off by default for ordinary users. The mobile entry uses Mobile app access (`app`). The desktop entry (`/toolbox?app=web`) uses Web app access (`web`), so Web-only supervisors do not need Mobile enabled. Each entry keeps its own session cache. Supervisors need the appropriate app access and the toolbox task permission. Administrators have toolbox access automatically.

Toolbox Talks opens on a Home dashboard with daily and weekly start buttons, a resumable device draft, recent records and outstanding actions. Home refreshes use an unfiltered summary independent of record searches. Returning home preserves unsaved edits. Starting a new talk warns before replacing an existing draft. Saved records retain search, downloads and shared draft editing.

Administrators edit three daily prompts (tasks for the day, high-risk activities, issues from previous shift) and six weekly prompts, then choose **Save shared templates**. Changes apply to new talks. Supervisors create a talk, enter the workshop/project, tasks or weekly focus, comments, attendee names and follow-up actions. New daily talks also record thirteen Yes/No/Not applicable inspection answers, high-risk activities, previous-shift issues and signatures. Inspection answers are required before signing a new daily talk; they are independent of section discussion confirmations. Existing records and signatures remain compatible. New talks default to Lennox Facades, the device’s current local time, and the signed-in supervisor’s display name. Supervisors select attendees from the active PanelStock user list; records retain the selected username and name as a signed snapshot. The directory returns only usernames and display names to accounts with toolbox access. There is no Discussed with the team checkbox; signing records the acknowledgement. After the discussion, each worker draws their signature on the supervisor's device. The supervisor signs last and completes the talk.

Draft edits are cached under the signed-in supervisor's username on that device. **Save draft** writes them to the shared backend. Drafts can be read and edited only by their owner or an administrator. **Delete draft** is available in Home, an open draft and saved draft rows, with confirmation. Device-only drafts are removed locally; saved drafts can be deleted by their owner or an administrator. Deletion checks the saved revision, removes the draft content and index entry, and keeps minimal deletion metadata and an audit entry to prevent stale devices from recreating it. Completed talks cannot be deleted.

Completed talks are available to accounts with toolbox permission and cannot be edited, including by administrators. Follow-up actions can be marked resolved separately, with the resolver and server time recorded.

Signatures include their device signing time and a SHA-256 digest of the discussion, names and agreed actions. Editing these fields, inspection results, selected attendee identities or attendance times clears signatures in the interface, and the backend rejects signatures for changed content. This records drawn acknowledgements on a shared device; it does not independently authenticate each worker or provide a certificate-based signature.

Dates shown on the dashboard, record cards, actions, signing timestamps and PDF/HTML exports use **dd-mm-yyyy**. Stored dates and native date-input values keep ISO format so existing records and signature hashes remain valid.

## Completed PDF emails

Administrators open **Settings** inside Toolbox Talks, enter up to 20 recipients and enable automatic email. The sender is fixed to **PanelStock Reports <reports@panelstockhq.com>**. Both daily pre-starts and weekly talks use the supplied PDF templates and the same comments-only export renderer, with signed attendance and supervisor sign-off. Drafts and failed completion attempts do not queue mail. Existing completed records are not emailed retroactively.

Completion saves the signed record and a recipient snapshot in one transaction. Email delivery runs in the background immediately and retries on the existing 15-minute cron. Saving remains successful if PDF preparation or email delivery fails. Settings shows the last 50 delivery statuses; Sent means accepted by Resend, not confirmation of inbox delivery. Recipient changes apply to new completions; disabling automatic email pauses pending jobs. Admins can retry failed or retrying jobs within the provider's safe deduplication window. Sent jobs cannot be resent. Unconfirmed deliveries stop after 23 hours and require provider review to avoid duplicate mail.

The production Worker uses its existing Resend secret and EMAIL_ENABLED setting; staging email remains disabled. No credentials appear in the settings UI. The page generator also produces server PDF assets from the bundled templates, font and logo; pretest checks both generated modules. PDF generation uses a copy of the immutable saved record and does not change its signatures or content hash.

## Exports and recovery

From an open talk, Home or Saved records, **Download PDF** creates a PDF directly on the device using the supplied form for the talk type: daily pre-starts use landscape `worker/assets/prestart.pdf`; weekly talks use portrait `worker/assets/weekly.pdf`. Weekly fields map project, date, facilitator to Presenter, focus to Subject, and each attendee’s name and signature. Attendance time-in, time-out, employer and the acknowledgement checkbox are removed from the interface and finished PDF/HTML copies. Previously saved values remain in the original records and JSON backups. Weekly talks do not show or require the daily inspection checklist. The daily form fills project, date, supervisor, thirteen inspection results, tasks, high-risk activities, previous-shift issues, attendance signatures. Finished PDF and HTML exports contain the typed comments, actions, signatures, supervisor sign-off and record metadata. Admin talking-point prompts are omitted from finished copies while remaining in the stored record and JSON backup. Long text continues on extra pages; attendance pages repeat for all attendees. Draft exports are marked DRAFT. Blank legacy checklist answers and attendance times are never inferred from discussion checks or signature timestamps. Unused blank pages are omitted. Weekly supervisor-entered comments fill the five corresponding printed sections; incident reporting / first aid has no printed box in Weekly.pdf and is included on accompanying notes pages. Existing weekly records with daily inspection data retain that data in the notes. Attendance sheets repeat for all attendees. **Download record** saves a standalone HTML copy containing the signatures. Upload either completed copy to OneDrive manually. Automatic OneDrive upload is not configured.

**Export shared records** creates a JSON export of the templates and all records accessible to the supervisor. It captures a fixed list of record identifiers before fetching them so concurrent new records cannot shift pagination and omit older records. Individual records are read at export time, not as a single point-in-time database snapshot. Store exports securely: they contain names and signatures.

**Back up current draft** and **Recover local draft** handle device draft recovery. Recovering a draft does not replace shared data; later server saves still enforce revisions. If another device has changed a record, reopen the shared version rather than overwriting it. An interrupted save can be retried with the retained mutation identifier.

Records are persisted as individually chunked documents in the existing SQLite Durable Object. They do not alter inventory records or the existing stock-restore process. Toolbox records are not included in the current inventory-only daily backup; independent toolbox exports should be part of the operational backup routine. No automatic record-deletion policy is introduced.

## Source and validation

Edit `worker/templates/toolbox.html` for the interface and `worker/src/toolbox.js` for the API and validation. Run `node worker/scripts/toolbox-page.mjs` to regenerate the tracked page module. The generator embeds the same signature-content function used by the backend, along with a self-contained browser PDF bundle built from pdf-lib/fontkit dependencies and the bundled DejaVu Sans font. No CDN or third-party network requests are used; the form and PDF rendering stay on the device. The PDF font covers common Latin, Greek and Cyrillic text; unsupported characters cause an explicit export error instead of being silently removed. The pretest check rejects stale generated output.

From `worker/`:

```sh
npm test
npx wrangler deploy --config wrangler.production.jsonc --dry-run
```

The existing production workflow deploys this module with the Worker after merging into `main`. Review the change and approve release before merging; merging triggers a production deployment. Test with synthetic workshop data in staging first, including supervisor access, signing, conflicts, action resolution and signed PDF export. Existing inventory migration flags, bindings and secrets must remain unchanged.

The interface works on tablets and phones and uses pointer input for finger, stylus or mouse signatures. Shared reads and saves require a connection. Cached device drafts are not a full offline login or offline synchronization system.

## Workshop Safety portal, SWMS and SDS

The production Worker serves the Workshop Safety portal at `https://safety.panelstockhq.com/`, with Toolbox Talks at `/toolbox`, SWMS at `/swms` and SDS at `/sds`. The custom-domain route provisions the host through the existing Cloudflare Worker deployment. Panelstock Mobile and Web Toolbox links exchange the existing short-lived sign-in ticket with this host; staging launchers retain their staging origin. Direct visits without a cached session instruct users to open from Panelstock.

Admins upload PDF documents up to 5 MB, classify them as SWMS or SDS, give each version a revision label, and archive or restore documents. Files are stored as private, chunked documents in the existing Durable Object. All reads require Toolbox permission. Existing versions and acknowledgements are retained. Supervisors choose active Panelstock users and collect their signatures on the shared device after document review. Each acknowledgement binds to the exact file hash, document version, user name and acknowledgement statement; replacement versions need new acknowledgements. Previous or archived versions cannot collect new signatures. Downloadable CSV registers contain the version/file hash, names, signing and server recording times, and collecting supervisor. These shared-device signatures record acknowledgements rather than independently authenticating individual workers.
